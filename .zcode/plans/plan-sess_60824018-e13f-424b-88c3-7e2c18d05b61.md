# TUI для agent-run: новый крейт `crates/agent-run-tui`

## Что уже выяснено (поверхность ядра готова, ядро не трогаем)

- Resident daemon слушает JSON-RPC 2.0 на `<home>/api.sock` (framed Unix socket): `crates/agent-run/src/transport/socket.rs`.
- Публичный переиспользуемый клиент: `agent_run::transport::socket::BrokerClient` (`new`, `call`, `call_with_timeout` — reconnect/таймауты уже реализованы).
- Методы брокера (`crates/agent-run-core/src/dispatch.rs:112`): `list_agents`, `transcript`, `answer`, `wait`, `ping`, `tools`, `models`, `limits`, `capacity_order`, `start`, `resume`, `cancel`, `steer`.
- Готовые read-model DTO с serde — `agent-run-domain/src/views.rs`: `AgentView` (статус, runtime, model, task_summary, elapsed, silence_seconds, phase, failure, delivery, lineage), `AgentPage` (пагинация + `revision`!), `TranscriptPage`/`MessageView` (курсор `seq`, role, content), `AnswerView`.
- «Живые» обновления без пуша: `Query` (`crates/agent-run-core/src/service.rs:185`) поддерживает `after_revision` + `wait_seconds` — `list_agents` умеет long-poll до смены ревизии хранилища.
- Статусы: `Status` из `agent-run-domain` (Created/Starting/Running/Cancelling + терминальные Succeeded/Failed/TimedOut/Cancelled/Lost, есть `terminal()`).
- Home-каталог: `agent_run_platform::fs::home` (env `AGENT_RUN_HOME`).
- Untrusted-контент транскрипта санитизируется `agent_run::transcript::sanitize` — TUI обязан переиспользовать её.
- `cargo xtask check` работает через `--workspace` — новый крейт подхватывается автоматически.

## Архитектура TUI

Данные — только через resident broker (никакого прямого чтения SQLite: процессные наблюдения и ревизии принадлежат демону). TUI — чистый наблюдатель, ничего не запускает.

Потоки данных:
1. Список сессий: первичный `list_agents {active:true, limit:200}`, далее long-poll `list_agents {after_revision:<R>, wait_seconds:25}` — демоновская смена ревизии будит перерисовку.
2. Транскрипт выбранной сессии: догоняющие страницы `transcript {agent_id, cursor, limit}` по курсору; пока сессия не терминальна — поллинг хвоста раз в ~1 с; буфер `BTreeMap<seq, MessageView>` с дедупликацией.
3. Ответ: `answer {agent_id}` по запросу пользователя.
4. Тикер 1 с — перерасчёт elapsed/silence локально.

Зависимости крейта: `agent-run` (lib-фасад: BrokerClient + transcript::sanitize), `agent-run-domain` (views/Status), `agent-run-platform` (fs::home), `tokio`, `ratatui`, `crossterm` (новые для workspace версии фиксируем в `[workspace.dependencies]`; mouse capture включён — колесо/клик/скролл), `serde_json`, `clap`.

## Экраны (полный UI-фарш: рамки с заголовками, цветные бейджи статусов, braille-спиннер, скроллбары, мышь)

1. **Список сессий** (главный): таблица — статус-бейдж (цвет по Status), agent_id/run_id (короткие), runtime, model, profile, task_summary, elapsed, silence (возраст последнего прогресса, восклицание при stall), phase, маркер ответа. Сортировка: активные сверху, затем по created_at desc. Tab — переключение «активные/все». Мышь: клик по строке = выбор, колесо = скролл. Enter — транскрипт.
2. **Транскрипт**: шапка (AgentView-сводка: статус, модель, elapsed/silence, failure_text); тело — сообщения с ролью (user/assistant/tool/system — цвет и префикс, tool-активность приглушённо), авто-follow хвоста (f), скролл ↑↓/PgUp/PgDn/Home/End/мышь, индикатор «догружаем историю», Esc — назад.
3. **Панель ответа** (клавиша a): AnswerView — inline content либо путь + sha256/размер.
4. **Статус-бар**: соединение (подключено/ретрай), revision, счётчик сессий, подсказки клавиш. q — выход.

Санитизация: любой контент сообщений проходит `transcript::sanitize` перед отрисовкой.

## Структура крейта

```
crates/agent-run-tui/
  Cargo.toml            # publish=false, lints.workspace
  src/main.rs           # clap: --home/--socket, alt-screen + mouse capture
  src/net.rs            # типизированная обёртка BrokerClient; трейт Transport для тестов
  src/app.rs            # модель+reducer: sessions, revision, selection, буферы транскриптов, follow
  src/events.rs         # tokio::select: crossterm events / тик / long-poll / transcript poller
  src/ui/{mod,list,transcript,answer,theme}.rs
```

## Тесты

- unit на reducer: сортировка/фильтр, слияние страниц транскрипта по `seq`, сброс буфера при смене сессии, обработка смены ревизии.
- golden-рендер через `ratatui::backend::TestBackend` на фиксированных размерах (оба экрана + статус-бар).
- net: mock `Transport` — long-poll переходы, таймауты, reconnect.
- Верификация: `cargo xtask check`, `cargo test -p agent-run-tui`. Транспорт ядра не меняется — live-смоук по правилам не требуется, но в доки добавим ручной сценарий против работающего демона.

## Режим работы с agent-ide (по вашему требованию)

Журнал отказов на этапе планирования: `ide_start` — 2 отказа («Assistance host metadata or attachment is unavailable»; повтор предписан не был → нативный fallback), оба запуска агентов были отменены до их `ide_start`. На этапе реализации каждый агент-исполнитель обязан сам вызвать `ide_start` и вести работу через `ide.outline/ide.symbol/ide.graph/ide.read/ide.edit`; каждый отказ фиксировать в отчёте (кто, какой вызов, текст отказа, какой fallback использован). Итоговая сводка использования agent-ide будет в финальном отчёте задачи.
