# Capacity and completion-delivery inventory

> **Historical analysis — the addresses below are not current.** This inventory
> records the state of the port at the time it was written, when the Rust code
> was a single `rust/` crate. That tree no longer exists; the port is now the
> `crates/` workspace, and the parity figures quoted here were superseded long
> ago. The addresses are kept verbatim because rewriting them would attach an
> old measurement to code it never described. For what is covered today, see
> `migration/status.md`, `migration/baseline/test-map.csv` and
> `migration/evidence/qualification-scope.md`.

## 1. Summary

- Estimated behavioral parity for this combined area is **about 48%** (capacity ~45%, delivery ~55%).  Rust has the main data types, expiry/forecast math, SQLite tables, Codex app-server probe, Desktop relay, and Claude UDS sender, but not the established source and public-projection contracts.
- `capacity order` is **not hook-compatible**: its sort tie-breakers and evidence reason/detail strings differ, and `limits` emits raw samples rather than Python's advisory objects (`rust/src/capacity/mod.rs:444`, `rust/src/capacity/mod.rs:455`; Python `src/agent_run/service.py:957`, `src/agent_run/capacity/ranking.py:405`).
- OmniRoute and labelled Codexbar collection are explicitly unsupported in Rust (`rust/src/capacity/sources.rs:520`), blocking configured Qwen/OmniRoute and multi-account installations.  This matches the port's claimed known difference, but is still a drop-in compatibility gap (`rust/docs/MIGRATION_STATUS.md:38`).
- Completion delivery preserves leased attempts and the two current hosts, but its notice text, evidence JSON shape, dispatcher locking/batch behavior, and unbound-notification expiry do not match Python (`rust/src/delivery/mod.rs:92`, `rust/src/delivery/mod.rs:257`; Python `src/agent_run/delivery/base.py:39`, `src/agent_run/delivery/dispatch.py:195`, `src/agent_run/state/delivery.py:172`).
- Daily-use replacement is blocked by the hook-facing routing output, missing production quota sources, and delivery compatibility with existing pending/waiting bindings and diagnostic evidence.

## 6. Risks and unknowns

- No live provider, Desktop, Docker, Keychain, or `~/.agent-run` access was used.  Host protocol compatibility is therefore source-verified only, not live-verified.
- Rust docs already acknowledge source-specific projection, evidence, OmniRoute, labelled Codexbar, and Keychain gaps (`rust/docs/MIGRATION_STATUS.md:38-45`); those deliberate development divergences break a drop-in replacement unless explicitly removed from the owner's supported installation.
- The present Rust schema claims version 16 (`rust/src/state/mod.rs:17`) while historical migration compatibility is owned by another area; capacity/delivery fixture work must not overwrite or silently normalize Python state.
- Rust's extra filesystem permission checks in Claude UDS may be security-positive, but exact behavior on macOS and existing registry files is unverified and must fail safely rather than turn into an incompatible false success.
