# Codex adapter and generated runtime-home inventory (CX)

## 1. Summary

- Estimated behavioral parity: **38%**. Rust has a usable Codex app-server launch/turn loop, model pagination, grants, and basic generated `config.toml` (`rust/src/adapters/codex.rs:378-708`, `rust/src/adapters/materialize.rs:400-544`).
- It is not a drop-in replacement: its runtime manifest is `.agent-run-rust-snapshot.json`, not Python's `.agent-run-snapshots.json` plus per-tree `.agent-run-snapshot.json`; Rust explicitly says the formats and Python immutable snapshots are incompatible (`rust/src/adapters/materialize.rs:16-25`, `src/agent_run/adapters/snapshot_tree.py:20-24`, `rust/docs/MIGRATION_STATUS.md:37-42`).
- Python-created Codex runs cannot be resumed by Rust, which is a daily-use replacement blocker for an existing `~/.agent-run` installation (`rust/docs/MIGRATION_STATUS.md:37`, `src/agent_run/adapters/snapshot_config.py:137-208`).
- The wire-path is only partially faithful: Rust does initialize/start/resume/turn/steer/interrupt, but lacks Python's bounded request transport semantics, permission-request allow hook, answer-proof sealing, event preservation, and complete failure normalization (`rust/src/adapters/codex.rs:416-699`; `src/agent_run/adapters/codex/app_server.py:141-402`).
- Rust has no focused adapter/materialization test file; its only direct Codex grant test is `rust/tests/domain_config.rs:278-300`. The extensive Python differential fixtures are not ported.

## 6. Risks and unknowns

- `rust/src/fs.rs` is the likely safe-file primitive, but its exact fsync/no-follow equivalence was not independently reviewed in this bounded inventory; CX-2 must audit it rather than assume parity.
- No live Codex CLI or real account/home was inspected. Native protocol and hook trust compatibility therefore require recorded fixtures and an authorized smoke test.
- The status document's snapshot incompatibility is corroborated by source, not merely accepted as a claim (`rust/docs/MIGRATION_STATUS.md:42`, `rust/src/adapters/materialize.rs:16-178`).
- Rust's state/lifecycle code may constrain how CX-1/CX-2 can persist Python-compatible evidence; those packages need coordinated API boundaries before implementation.
