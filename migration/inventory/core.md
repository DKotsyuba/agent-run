# Core lifecycle and configuration inventory

> **Historical analysis — the addresses below are not current.** This inventory
> records the state of the port at the time it was written, when the Rust code
> was a single `rust/` crate. That tree no longer exists; the port is now the
> `crates/` workspace, and the parity figures quoted here were superseded long
> ago. The addresses are kept verbatim because rewriting them would attach an
> old measurement to code it never described. For what is covered today, see
> `migration/status.md`, `migration/baseline/test-map.csv` and
> `migration/evidence/qualification-scope.md`.

## 1. Summary

- Estimated behavioral parity for core lifecycle/configuration: **about 43%**. Rust has typed request/status/config/profile primitives, durable admission, a separate supervisor, process identity observation, and answer/view queries (`rust/src/service.rs:107-185`, `rust/src/supervisor.rs:17-106`).
- Daily-use replacement is blocked by incompatible frozen launch identity and explicit rejection of Python-created continuations (`rust/src/service.rs:25-53`; Python continuation contract is `src/agent_run/resume.py:169-232`). This breaks an existing installation's completed Python runs even when their database remains readable.
- Canonical roles are parsed but not resolved into the Python's immutable skill/MCP/auth/config-revision plan; consequently snapshots and resumes cannot prove the same grants/assets (`rust/src/profiles.rs:48-146`; `src/agent_run/role_plan.py:80-116,288-359`).
- Rust's supervisor covers READY-before-materialization, cancellation polling, engine cleanup, and terminal proof (`rust/src/supervisor.rs:81-240`), but its `Command::pre_exec(setsid)` launch is not Python's `posix_spawn`-first protocol and lacks its bootstrap-pipe/reaper evidence path (`rust/docs/MIGRATION_STATUS.md:41-47`; `src/agent_run/launch.py:154-299`). This is a drop-in reliability gap, not an acceptable intentional divergence.
- Config TOML v1 is broadly accepted with strict fields and reserved native roots (`rust/src/config.rs:48-214,300-548`), but error surface, lexical binary handling, environment materialization, and credential/account-home conventions are not compatible in full.

## 6. Risks and unknowns

- The Rust port explicitly rejects Python launch identities and uses a Rust-only snapshot manifest (`rust/docs/MIGRATION_STATUS.md:36-43`); this is incompatible with the required existing-installation replacement until CO-1/CO-2 differential fixtures pass.
- `Command::pre_exec` after a multithreaded broker is a process-safety risk; the documented known difference confirms no equivalent OS review yet (`rust/docs/MIGRATION_STATUS.md:46-47`).
- `rust/src/adapters/materialize.rs` needs a separate adapter-area audit for exact generated homes/files; this inventory only establishes that the core inputs and identity proof are incomplete.
- No live home was inspected, by instruction. Config/database/path compatibility statements above derive only from source and should be verified with redacted Python fixtures.
