# Transports, CLI, and operations inventory

> **Historical analysis — the addresses below are not current.** This inventory
> records the state of the port at the time it was written, when the Rust code
> was a single `rust/` crate. That tree no longer exists; the port is now the
> `crates/` workspace, and the parity figures quoted here were superseded long
> ago. The addresses are kept verbatim because rewriting them would attach an
> old measurement to code it never described. For what is covered today, see
> `migration/status.md`, `migration/baseline/test-map.csv` and
> `migration/evidence/qualification-scope.md`.

## 1. Summary

- **Estimated behavioural parity: 38%.** Rust has a compile-time shared table for the eleven public tools (`rust/src/dispatch.rs:10-25`), a newline JSON-RPC socket (`rust/src/transport/socket.rs:37-124`), and an `rmcp` stdio proxy (`rust/src/transport/mcp.rs:18-83`). This is not evidence of wire compatibility.
- The resident broker boundary for CLI `start`/`resume` is present (`rust/src/cli.rs:521-543`), but ordinary CLI mutations still bypass it (`rust/src/cli.rs:546-558`), unlike the Python transport contract (`src/agent_run/cli.py:986-1025`).
- Daily-use blockers are missing `bind`, `context`, and `hook` commands; incompatible CLI arguments/output and launchd generation; and no compatible release/install/rollback implementation. Rust itself declares it must use an isolated evaluation home (`rust/docs/OPERATOR_GUIDE.md:3-7`).
- Socket basics are covered, but Python's two thread-affine bounded lanes, 32-connection/64-queue policy, 30-second request policy, reserved control frame, and custom socket override are absent or changed (`src/agent_run/api_socket.py:46-57`, `493-593`; `rust/src/transport/socket.rs:81-124`, `190-203`).
- Migration-status “known differences” are compatibility gaps, not acceptable drop-in choices: production DB/schema refusal, Python-run resume refusal, smaller answer and delivery-evidence shapes, and changed snapshots all break an existing installation/tooling (`rust/docs/MIGRATION_STATUS.md:34-46`).

## 3. Public contract surface

### CLI

Python emits one sorted JSON object plus newline on stdout (`src/agent_run/cli.py:488-492`); expected/domain errors are `{"error":{"type","message",...}}` on stderr and exit 2 (`src/agent_run/cli.py:495-504`, `1033-1054`). Normal success is 0; `doctor`/one-shot `capacity collect` with `ok=false` are 2; `start --wait` maps terminal state through `AGENT_EXIT_CODES` (`src/agent_run/cli.py:448-469`). Rust prints compact JSON in normal paths (`rust/src/cli.rs:278-289`), prints `{error:{kind,message}}` to stderr on all returned errors and exits 2 (`rust/src/main.rs:3-13`): **output/error parity partial**.

### MCP and socket

All public tool inputs are JSON objects, reject additional fields, and share the following Python schema table (`src/agent_run/dispatch.py:46-145`). Rust ships the matching table resource (`rust/resources/tools.json:1-354`) and routes names in one function (`rust/src/dispatch.rs:85-148`): **schema-name parity ported; result/error parity depends on service and remains partial**.

| Tool | Required input; optional input/defaults | Result contract / error mapping | Parity |
|---|---|---|---|
| `start` | `runtime,model,profile,task,workdir`; optional `write=false,fast=false,effort,timeout_seconds,read_roots=[],output_schema,orchestrator{transport,external_session_id,external_turn_id?},request_id,account,required_constraints=[]` | durable start result (at least `agent_id,created`); bad types/unknown/duplicate constraint → validation | partial: table matches fields (`rust/resources/tools.json:12-126`), decoder is generic `StartRequest` (`rust/src/dispatch.rs:85-88`); validate exact output/defaults. |
| `resume` | `agent_id,task`; optional `timeout_seconds,request_id,orchestrator` | new `{agent_id,created}`; validation/domain error | partial (`rust/src/dispatch.rs:59-99`). |
| `cancel` / `answer` | `agent_id` | cancellation/verified answer service envelope | partial (`rust/src/dispatch.rs:34-38`, `100-110`); Python answer metadata/evidence compatibility belongs to state/domain. |
| `steer` | `agent_id,text` | service response; validation/domain error | partial (`rust/src/dispatch.rs:40-44`, `104-107`). |
| `list_agents` | all optional: `active=false,orchestrator,offset=0,limit=100,after_revision,wait_seconds=0` | page with exact total/revision; Python supports 60s long-poll | partial (`rust/resources/tools.json:165-219`, `rust/src/dispatch.rs:116`); socket long-poll policy differs. |
| `transcript` | `agent_id`; `cursor=0,limit=200` | one cursor page, raw reference remains reference | partial (`rust/src/dispatch.rs:46-55`, `112-115`). |
| `doc` | optional `topic` | `{topic,text}` | partial: Rust only five topic values (`rust/src/cli.rs:329-337`). |
| `models`, `limits`, `capacity_order` | no fields | service capacity/model data | partial (`rust/src/dispatch.rs:122-132`); upstream capacity result compatibility is a dependency gap. |

MCP Python success is `{content:[{type:"text",text:"result in structuredContent"}],structuredContent:<data>,isError:false}` and domain failure is `{content:[...JSON error...],structuredContent:{error:{code,message,...}},isError:true}` (`src/agent_run/mcp.py:285-304`); unknown tool is a tool error, not a JSON-RPC throw (`src/agent_run/mcp.py:218-256`). Rust returns SDK `structured(value)` and `structured_error({error:error.public()})` (`rust/src/transport/mcp.rs:47-70`): **partial/incompatible until serialized transcripts are compared**. Python deliberately uses new broker clients and cancellation-safe bounded stdin (`src/agent_run/mcp.py:121-130`, `38-89`); Rust's independent broker call is `socket::client` (`rust/src/transport/mcp.rs:63-76`) but has no equivalent bounded reader implementation.

Socket methods are the eleven tools plus private `tools`, `ping`, `wait` (`src/agent_run/api_socket.py:54-57`; Rust `rust/src/transport/socket.rs:49-79`). `tools` Python returns the bare array, while Rust dispatcher returns `{"tools":[...]}` (`src/agent_run/api_socket.py:277-280`; `rust/src/dispatch.rs:134-138`): **breaking**. `ping` Python is exactly `{"ok":true}`; Rust adds `version` (`src/agent_run/api_socket.py:276-279`; `rust/src/dispatch.rs:139-142`): additive but byte-shape divergent. `wait` accepts `agent_id` plus optional positive finite `timeout_seconds`; Python omission waits indefinitely and expiry returns normal `{timed_out:true,status,...}` (`src/agent_run/api_socket.py:186-208`, `226-254`; docs `docs/api.md:152-161`). Rust accepts `wait_seconds` with an alias, calls `Service::wait` (`rust/src/dispatch.rs:80-84`, `143-145`): **unverified result compatibility**.

Python wire errors: parse/oversize `-32700`; malformed/batch/bad id `-32600`; unknown `-32601`; bad params `-32602`; domain `-32000` with `data.code/message` plus bootstrap fields; overload/deadline/closing `-32001/-32002/-32003`; internal `-32603` (`src/agent_run/api_socket.py:170-184`, `256-307`; `docs/api.md:227-239`). Rust returns `Error::rpc_code()` (`rust/src/error.rs:60-66`) and `data:{kind}` even when absent (`rust/src/transport/socket.rs:34-72`); it maps `BrokerUnavailable` to `-32001` rather than the server overload semantics: **partial and compatibility-breaking**.

Python socket accepts a selected `--socket`, mode 0600, same protocol caps (1 MiB), persistent multi-request connection and same-user private ownership (`src/agent_run/api_socket.py:334-405`, `542-580`, `696-714`). Rust has 1 MiB LF frames, 0600, peer UID check and stale socket cleanup (`rust/src/transport/frame.rs:1-44`, `rust/src/transport/socket.rs:81-203`), but only `<home>/api.sock`, different lock name (`api.lock` vs `.api.sock.lock`) and changed deadlines/gating: **partial**.
